RECENT CHANGES (April -- September 2026)
============================================================

v0.9.9 (2026-09-26) -- Pixel-Exact Field Evidence + EKS 1.36
--------------------

  SECURITY (drec-origin)
  ~~~~~~~~~~~~~~~~~~~~~~
  - The API now refuses to start in production-like environments
    when a JWT signing secret is missing or left at a known
    placeholder, instead of falling back to an in-code default.
    A guessable signing key lets anyone mint a valid token for
    any account, and the fallbacks meant that misconfiguration
    booted cleanly and looked healthy. Development and test keep
    a warned fallback so local work and CI are not blocked.
  - Session tokens are stored as a SHA-256 hash rather than the
    raw JWT, so read access to user_login_session no longer
    yields usable bearer credentials. NOTE: this invalidates
    existing sessions on deploy -- everyone logs in again once.

  ISSUANCE (drec-origin)
  ~~~~~~~~~~~~~~~~~~~~~~
  - Reads are marked certified, certificate-log rows written, MWh
    accounting advanced and the reservation ended only AFTER the
    mint succeeds. All of that used to happen first, so a failing
    issue() left reads flagged certified with "Requested" log
    rows and no certificate on chain. That state then blocked
    every automatic retry -- the certified flag hides the reads
    and the log rows suppress re-issuance -- so the token never
    landed without hand cleanup. This is the fault behind the
    2026-06-20 prod missing-tokens incident (~30 site-months
    stranded across Hamara Grid and Fourth Partner); prod was
    remediated at the time, this is the fix for the cause.

  AI EXTRACTION (drec-origin)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~
  - SLD field extraction moved from Haiku 4.5 to Opus (reading a
    full single-line diagram is the densest visual-reasoning task
    in the pipeline, and Haiku under-performed on it), then to
    Opus 5.5 once it shipped. The 5.5 move was A/B'd on two real
    SLDs with an identical prompt: same value on 15 of 17 fields,
    the two differing ones low-confidence on both models. It is
    not an accuracy change -- it is ~2x faster, 20% cheaper per
    token, and ~25% fewer output tokens, which is headroom
    against the max_tokens truncation this extractor has hit.
  - The Opus switch initially broke extraction outright: the
    request still carried `temperature`, which Opus rejects with
    a 400. Every SLD extraction failed for a day while documents
    already in ai_response_cache kept working, so the UI showed
    an empty verify queue rather than an error. Removed, and an
    hourly check now flags any endpoint with several failures and
    no successes, so a wholesale extractor failure announces
    itself instead of looking like "Verify does nothing".
  - Meter-ID extraction now reads the SN *column* rather than
    guessing from string shape. A firmware version and a serial
    are indistinguishable as strings -- both alphanumeric, both
    mixed letters and digits, same length -- so the previous
    heuristics were harvesting Huawei "Software Version" values
    (V100R001C00SPC153) as meter IDs while the real serials sat
    in the next column. Position is the only real discriminator.
    "SN" appears twice on those pages (a search box above the
    table as well as the header), so every candidate header is
    scored by how many serial-like values sit beneath it.
  - Satellite and map views (a map pin, a drawn boundary polygon,
    an overhead array) now classify as FACILITY_BOUNDARY. The
    vision rules never mentioned that category, and PROJECT_PHOTOS
    explicitly excludes screenshots, so aerial screenshots fell
    into the catch-all "screenshot => METERING_EVIDENCE" branch.

  - EPC / design-procurement-construction contracts now classify
    as PROOF_OF_OWNERSHIP. The definition listed only deed, lease,
    PPA, purchase and bill-of-sale, so a Vietnamese EPC contract
    submitted as proof of ownership landed in Other Documents.
    The rules now also say outright that documents are often not
    in English and should be classified by structure.
  - Meter-ID extraction also reads portal Info-page fields
    (capacity, commissioning date, device type) from the same
    screenshot, since a registrant uploading one for meter IDs
    is usually retyping the rest of it by hand anyway.

  UI (drec-ui)
  ~~~~~~~~~~~~
  - Field highlights in SLD verify are now pixel-exact, from a
    self-hosted PP-OCR service rather than in-browser tesseract.
    Tesseract could not lock onto dense diagram text, so the
    highlight fell back to the model's estimated bbox, which
    lands far from the value. Qwen2.5-VL grounding was tested
    head-to-head and is no better -- its boxes miss by hundreds
    of pixels even rescaled, because any model estimating
    coordinates is guessing. Deterministic OCR detects the text
    pixels, so there is nothing to guess.
  - Derived values (a count, a boolean) have no literal text to
    box, so instead of drawing a confident-looking estimate the
    view highlights the *evidence* -- the three "INV 0n" labels
    behind "3 generating units" -- and says N/A outright when
    nothing on the drawing can be pointed at.
  - Added a magnifier for the highlighted region: SLD labels are
    unreadable at page scale and zooming the page does not help.
    It parks in the quadrant the pointer is not in, stays put
    while the drawing scrolls, and magnifies the text itself
    rather than the padded outline.
  - Meter IDs carry a box each and are cross-checked against the
    image. An ID the model returned that OCR cannot find anywhere
    is flagged, since a wrong meter ID silently attributes
    generation to the wrong device. Near-matches are boxed and
    named, which is what makes a wrong-column read visible.
  - Maps use keyless OpenStreetMap tiles; the CARTO basemap had
    started rendering an "API KEY REQUIRED" watermark.
  - Auto-sort documents moved to the top row beside Organization
    -- dropping the documents in is the first thing a registrant
    does, so the button belongs before the form.

  - Scanned and non-English PDFs go to the vision model instead
    of the text path, which returned near-empty strings for them
    and produced confident nonsense downstream.
  - Document preview handles the formats registrants actually
    upload: .txt renders as text and .csv as a spreadsheet rather
    than a broken image, spreadsheets keep a sticky header row
    while scrolling and no longer offer an OCR button.
  - Add-device fixes from real submissions: SF-02 auto-selects
    "Upload your own" when one is detected, SiteOperator orgs
    appear in the registrant Organization dropdown, the live-
    issues sidebar shows in add mode when a disagreement blocks
    submit, and the (14) Meter ID label stops clipping.
  - Panel detection captures at zoom 19 and waits for tiles to
    finish loading; it was detecting against half-rendered
    imagery and then reporting zero panels with a hint that named
    the wrong cause.

  DEVICE MODEL (drec-origin + drec-ui)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  - Capacity split into AC and DC. `capacity` stays AC (what the
    UI, GCC reports and the registry already treat it as) and a
    nullable `dc_capacity` was added; only the production-ceiling
    and yield code reads DC, via dcCapacity ?? capacity. A site
    whose real DC array over-produces relative to its AC rating
    (normal ~1.3x oversizing) no longer has legitimate metered
    energy rejected as over-the-max. Null everywhere on deploy,
    so behaviour is unchanged until a DC value is entered.

  - deviceTypeCode is optional and derived from the description
    at register time. @IsOptional does not skip an empty string,
    so a blank field was rejected by the enum validator and an
    otherwise complete site could not be submitted.
  - Metering-evidence uploads raised from 10 files to 20; sites
    with many meters were hitting the cap legitimately.

  INFRASTRUCTURE (drec-infrastructure)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  - EKS upgraded from a 1.33-era cluster to 1.36, clearing the
    extended-support surcharge deadline (1.34 standard support
    ended 2026-12-02; 1.36 runs to 2027-08-02) and the cluster
    policy switched to STANDARD so the surcharge cannot recur
    silently. Karpenter 1.6.8 -> 1.14.1 first, since it gates
    which Kubernetes versions can be provisioned.
  - The upgrade surfaced four faults that had each been silently
    blocking it, and any one of them would block the next:
    a `10%` disruption budget rounds DOWN TO ZERO on a pool of
    fewer than ten nodes, so Karpenter could disrupt nothing --
    no consolidation, no drift remediation, no AMI updates, which
    is why every node was still on 1.33 a month after the 1.34
    upgrade; `karpenter.sh/do-not-disrupt` on the deployment
    templates made those nodes permanently undrainable (replaced
    with two replicas plus a PodDisruptionBudget, which protects
    the same thing while still allowing recycling); EKS addons
    are not upgraded with the control plane, and a kube-proxy
    outside the version skew left pods Pending with no CNI; and
    the managed nodegroup was t3.small (1.46GB), which OOM-killed
    kubelets and hit the pod-density cap -- replaced by a
    t3.medium nodegroup carrying only Karpenter and core addons.
  - AMI selection moved from pinned IDs and dated aliases to
    al2023@latest, which tracks the cluster version and resolves
    the right variant per instance type, including NVIDIA for GPU
    nodes. Stale pins were a recurring cause of upgrade churn.
  - Karpenter's interruption queue never existed: the controller
    was configured with INTERRUPTION_QUEUE but no SQS queue had
    been created, so spot interruption notices were never handled
    and spot nodes were terminated without being drained. Queue,
    EventBridge rules and IAM added.
  - AWS Health events are now ingested and mailed already decoded.
    The Health API needs a Business/Enterprise Support plan and
    returns SubscriptionRequiredException here, so EventBridge
    fans the events into SQS and a Lambda publishes a readable
    summary, prefixed [ACTION NEEDED] for the categories that
    carry a deadline. Previously these arrived as raw notices
    that had to be read by hand.
  - The upgrade is now reproducible: nodegroup and addon versions
    are scripted, PodDisruptionBudgets are checked in, and a
    runbook records the ordering (Karpenter, control plane,
    addons, nodes) and the four blockers above. The manifests had
    still described the pre-upgrade state, so applying them would
    have undone the fix.

  BUILD / DOCS (drec-origin)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~
  - MinIO and the mc client are pulled from quay.io at pinned
    release tags. Docker Hub stopped serving both images (401 on
    pull), which broke the local dev stack at startup.
  - Added a Code of Conduct, a security policy and NOTICE, and
    refreshed the API guide with a deployment/ops page -- the
    repo is public and had none of the files a reader looks for
    first.
  - Upload failures return the actual multer error rather than a
    generic message, so a rejected file says why.

  OPS
  ~~~
  - RDS: PowerTrust backup retention raised 1 -> 35 days, matching
    the other instances; a day of point-in-time recovery on a
    customer-facing environment was an oversight. copy-tags-to-
    snapshot enabled on all three.


v0.9.8 (2026-07-07) -- CI Green Restore + Unsaved-Changes Guard

  BACKEND / BUILD (drec-origin)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  - Code Quality pipeline restored to green after being red since
    2026-03-26. The pnpmfile typeorm security override had broken
    rush install permanently, hiding three months of drift; fixed
    the install, then repaired 75 prettier files, 16 eslint errors

    test-exclude >=7. Jest coverage works again and gates CI.
  - Docker note: the deployed image installs standalone from
    apps/drec-api/package.json (pnpm.overrides pins typeorm
    0.3.28), NOT the rush lockfile. Both paths verified.

  UI (drec-ui)
  ~~~~~~~~~~~~
  - Device add/edit now warns before leaving the page when field
    contents would be lost (in-app navigation via CanDeactivate
    guard, tab close/refresh via beforeunload). Successful submits,
    edit updates and per-row SF-02 saves mark the form pristine so
    they never false-trigger. Platform auto-fills (geocoder,
    impact-story inference, extractor fill-empty, derived defaults)
    deliberately do NOT count as unsaved user edits -- and no
    longer get mis-tagged as Manual provenance at submit.
  - drec-ui Code Quality + Check Generic pipelines restored to
    green (red since mid-June): a literal NUL byte in

v0.9.4 (2026-05-08) -- Haiku Form Pre-Fill + Registrant ACL Backfill
--------------------

  STAGING (deployed)
  ~~~~~~~~~~~~~~~~~~
  - New: vision-based Haiku extraction of structured fields from
    uploaded documents, with banners next to each upload slot and
    "Apply to form" buttons that pre-fill matching form controls
    (only when confidence ≥ 0.7 and the field is empty -- never
    overwrites manual input). Five extractors:
      • SLD (vision): AC/DC capacity, inverter count + size + make,
        modules, grid voltage, grid-tied, zero-export, transformer
      • SF-02c letter (text-first, vision fallback): project name,
        owner legal name + address + country, signing date,
        signatory + email
      • COD proof (text-first): commissioning date, facility name,
        capacity, owner, utility/issuer; opportunistic measurement
        IDs when the proof includes an equipment list
      • SF-02 registration form (text-first): facility name,
        capacity, COD, device type, owner, address, country,
        latitude / longitude, inverter count, module count
      • Metering screenshot / nameplate (vision): inverter /
        measurement serial numbers
  - SLD multi-page: render up to 2 pages at 2048px long-edge so
    template-style SLDs that put the schematic on page 2+ extract
    correctly.
  - Auto-classifier: new "OK + Extract" button that accepts the
    sort and runs every matching extractor against the classified
    files in one gesture.
  - Meter-IDs banner aggregates IDs from any number of metering
    screenshots / nameplate photos / COD proofs into a single
    deduped list. Apply merges with whatever's already in the (14)
    Meter or Measurement IDs field rather than skipping on
    non-empty input. Server-side regex filter rejects anything
    that doesn't look like a real SN (must be 8-24 contiguous
    alphanumeric, no dashes, no kW/kWp/kVA/Hz/V suffix) regardless
    of what the model returns.
  - Each extractor goes through the existing per-org Anthropic
    credit model (50-call free grant, registrants can drop in their
    own sk-ant-... key for unlimited use) and writes a row to
    ai_audit_log per call so per-doc-type token cost is trackable.
  - Migration 1763500000000: re-backfill Registrant role ACL
    permissions. Stage + prod had zero aclmodulepermissions rows
    for Registrant despite earlier seed migrations being recorded
    as applied -- result was a 403 on every guarded endpoint
    (visible as "Error 403: Forbidden resource" on the registrant
    dashboard). Idempotent re-run; a no-op on already-correct envs.

  STAGING (deployed)

    in practice was bound to slot 47 "Proof of Ownership") becomes
    PROOF_OF_OWNERSHIP. SF_02C now unambiguously names slot 46 (the

    filenames across slots — including server-saved files in edit
    mode, which previously slipped past the in-memory check on
    re-upload. Toast surfaces which slot the conflict is in.
  - Auto-classifier improvements:
      • Prefer the embedded PDF text layer over Tesseract OCR for
        generated PDFs (lossless; OCR was mangling apostrophes /
        kerning and dropping keyword scores).
      • New filename heuristic: "OD" (uppercase token) → SF_02C.
      • Filename "Proof of Ownership" routes to PROOF_OF_OWNERSHIP.
  - Tier-3 Haiku fallback. New endpoint POST /api/ai/classify-document
    invokes Claude Haiku 4.5 when local keyword scoring returns
    confidence < 0.6. Backend ai_audit_log table records per-call
    token counts (migration 1763300000000) so monthly spend can be
    reconciled against the workspace cap. Graceful fallback: any
    Haiku error / rate-limit / timeout silently leaves the keyword
    result intact.
  - Per-org Anthropic credit model (migration 1763400000000).
    org_api_licenses gains anthropic_api_key (encrypted) and
    anthropic_credits_remaining (default 50). Reviewers / Admin orgs
    use the platform key with no deduction; registrants get a 50-
    call free grant per org and can paste their own sk-ant-... key
    in /settings/licenses for unlimited use. ANTHROPIC_API_KEY env
    is the platform-key fallback when no Admin has saved one.
  - Auto-screen: 'skip' is no longer treated as 'fail' in
    overallStatus. A device with 6 pass + 2 skip + 0 fail now
    correctly reports Automation as ✓ pass.
  - Stale labels post-rename: "Owner's Declaration" → "Proof of
    Ownership" in slot abbreviations, classify-mismatch table, and
    Excel export column.
  - Minor polish: device-reviews list closed the 32px footer-reserve
    gap; auto-classifier suggestion no longer offers to move OD
    letters into the Proof-of-Ownership slot.

BUG FIXES
=========

Timestamp Format Regression
---------------------------
After upgrading TypeORM to 0.3.28, all API timestamps switched from the
standard "Z" suffix to "+00:00", breaking integrations (e.g. Powertrust
portal validation). Root causes:

  - TypeORM 0.3.28 changed internal timestamp serialization from
    .toISOString() (which outputs Z) to a Luxon-based format that
    outputs +00:00
  - Outbound Evident API calls also used Luxon's ZZ format token,
    producing +00:00 instead of Z

Fixes applied:
  - Added a global NormalizeDatesInterceptor that rewrites all +00:00
    suffixes to Z in API responses
  - Fixed the Evident issuance service to use a literal 'Z' in the
    outbound timestamp format
  - Fixed timezone.ts transformer to use .toISOString() instead of
    .format()

CORS Whitelisting
-----------------
Added stage-portal.drecs.org to the backend CORS origin allowlist after
the new staging portal URL was deployed.

Prettier CI Failures

Fixed Prettier formatting in Postman collections and data-models.md that
were causing the "Check Docs" CI workflow to fail.

Solar Panel Detection via Satellite Imagery (Roboflow ML)
---------------------------------------------------------
Added an AI-powered solar panel detection feature to the device reviews
satellite map. Reviewers can click "Detect Panels" to verify that solar
installations actually exist at the claimed coordinates.

  - Uses Roboflow's zero-shot segmentation API with a "solar-panel"
    text prompt
  - Captures the visible map tiles to a canvas, crops to the center 70%,
