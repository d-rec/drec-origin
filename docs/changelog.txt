BUG FIXES
=========

Timestamp Format Regression
---------------------------
After upgrading TypeORM to 0.3.28, all API timestamps switched from the
standard "Z" suffix to "+00:00", breaking integrations (e.g. Powertrust
portal validation). Root causes:

  - TypeORM 0.3.28 changed internal timestamp serialization from
    .toISOString() (which outputs Z) to a Luxon-based format that
    outputs +00:00
  - Outbound Evident API calls also used Luxon's ZZ format token,
    producing +00:00 instead of Z

Fixes applied:
  - Added a global NormalizeDatesInterceptor that rewrites all +00:00
    suffixes to Z in API responses
  - Fixed the Evident issuance service to use a literal 'Z' in the
    outbound timestamp format
  - Fixed timezone.ts transformer to use .toISOString() instead of
    .format()

CORS Whitelisting
-----------------
Added stage-portal.drecs.org to the backend CORS origin allowlist after
the new staging portal URL was deployed.

Prettier CI Failures
--------------------
Fixed Prettier formatting in Postman collections and data-models.md that
were causing the "Check Docs" CI workflow to fail.

Device Registrant Display
-------------------------
The device reviews panel showed "--" for the Registrant field because the
SQL query joined user on the wrong key. Fixed by joining on
user.api_user_id = device.api_user_id (UUID) and displaying the user's
full name or email.

Device Registration DTO (POST /device, PATCH /device/:id)
----------------------------------------------------------
The following fields were added to the device registration and update
endpoints. These are now required for new device registrations:

  - serialNumber (required) -- unique device serial number, replaces the
    former developerExternalId as the primary device identifier. Must
    contain only letters, numbers, underscores, hyphens, or semicolons.
  - dataSource (required) -- the data source used for meter reads
    (e.g. "Engie", "BBOX", "Manual")
  - dataSourceBrand (required) -- the brand/model of the data source
    hardware
  - otherDataSource (optional) -- free-text field when dataSource is
    "Other"

The developerExternalId field is still accepted but is now optional.

Solar Panel Detection via Satellite Imagery (Roboflow ML)
---------------------------------------------------------
Added an AI-powered solar panel detection feature to the device reviews
satellite map. Reviewers can click "Detect Panels" to verify that solar
installations actually exist at the claimed coordinates.

  - Uses Roboflow's zero-shot segmentation API with a "solar-panel"
    text prompt
  - Captures the visible map tiles to a canvas, crops to the center 70%,
    converts to base64 JPEG, and sends to a backend proxy endpoint
  - Draws polygon overlays on detected regions with confidence labels
  - API key is kept server-side (ROBOFLOW_WORKFLOW_URL and
    ROBOFLOW_API_KEY env vars) -- the frontend never sees it

Earlier attempts using classical computer vision (color-based and
edge/shape-based detection via OpenCV.js) produced too many false
positives on trees and failed to detect actual panels. The ML approach
works significantly better.

DATA SECURITY (Methodology §3)
-------------------------------

RDS Security Group Lockdown (§3.2.1, §3.2.3)
  - Both prod and staging RDS instances were on the VPC default security
    group which allowed all TCP from 0.0.0.0/0 (internet-wide)
  - Created dedicated security groups:

      sg-drec-staging-db -- inbound 5432 from EKS cluster SG only
  - Removed the default SG from both RDS instances
  - Databases are now unreachable from outside the VPC

Least-Privilege Database User (§3.2.3, §3.2.8)
  - The API was connecting to prod as the "postgres" superuser
  - Created a dedicated "drec_app" user with SELECT/INSERT/UPDATE on all
    tables but DELETE revoked on 15 evidentiary/production tables:
      meter_reads, aggregate_meterread, history_intermediate_meteread,
      device, device_group, certificate_read_model, issuer_certificate,
      old_issuer_certificate, check_certificate_issue_date_log_for_device,

      device_lateongoing_certificate_cycle,
      next_issuance_date_log_for_device_group, delta_firstread,
      history_next_issueance_log, organization
  - Updated prod K8s secret (drec-prod-env) and rolled the deployment

History Triggers for Data Immutability (§3.2.2)
  - Created a "history" schema with a "changes" table that records
    table_name, operation, row_id, old_data (jsonb), new_data (jsonb),
    changed_by, and changed_at for every INSERT/UPDATE/DELETE
  - Applied triggers (trg_history_*) to all 15 protected tables
  - drec_app has read-only access to history.changes
  - Provides the evidentiary "before" snapshot an auditor needs to
    reconstruct why a certificate was issued

pgAudit for Write Logging (§3.2.2)
  - Enabled the pgaudit extension on prod RDS (Postgres 14)
  - Created custom parameter group (drec-prod-pg14) with:

  - All INSERT/UPDATE/DELETE statements are now logged to CloudWatch Logs

  - CloudWatch logs are outside the database -- inaccessible even to a

VERIFICATION & REVIEW TOOLS (April 2, 2026)
=============================================

NEW FEATURES
------------

Upload Logging (Backend)
  - All device registration, meter-read submission, and bulk-upload
    requests are now logged to the upload_log table with user, IP,
    user-agent, file metadata, and action type
  - Fire-and-forget pattern — logging failures do not block the
    primary request
  - Integrated into device controller (POST + PATCH), reads controller
    (POST), and bulk-upload controller (POST)

Device Coordinate Fingerprint Grid (~22 m)
  - Device latitude/longitude are now snapped to the nearest 0.0002°
    (~22 m) for stable duplicate detection fingerprints
  - Changed from toFixed(4) (~11 m) to Math.round(val / 0.0002) * 0.0002

±1.5σ Anomaly Band on Historical Consistency (§3.7)
  - Extended the historical consistency check with sigma band outlier
    detection
  - Computes mean ± 1.5 standard deviations over normalized kWh values
  - Flags individual reads that fall outside the band as anomalies
  - Added sigma band stats (low, high, outlier count) to the
    consistency summary response and frontend modal

Photo GPS EXIF Verification (VA Layer)
  - New endpoint: GET /device-reviews/:deviceId/photo-gps
  - Downloads PROJECT_PHOTOS from S3, extracts GPS coordinates via the
    exifr library, and computes haversine distance to declared device
    location
  - 300 m threshold: pass/fail per photo, overall verdict
  - Frontend modal shows per-photo results with distance and status

Auto-Screen Report (VA Layer)
  - New endpoint: GET /device-reviews/:deviceId/auto-screen
  - Runs 9 verification checks in parallel using Promise.allSettled():
    ownership, duplicates, sourceAccess, consistency, ceiling,
    crossSource, photoGps, controls, sldCompare
  - Each section returns status (pass/warn/fail/skip) with flag messages
  - Overall status = worst individual status
  - Frontend modal with color-coded section cards, overall banner, and
    close button

SLD Capacity Compare (VA Layer)
  - New endpoints:
      GET  /device-reviews/:deviceId/sld-compare

ROLE & ORGANIZATION CLEANUP
----------------------------

Renamed apiUser → Registrant (Organization Type & Role)
  - The legacy "apiUser" / "MarketIntermediary" organization type and role
    have been renamed to "Registrant" throughout the platform
  - A registrant registers devices, manages site operators, and submits
    meter reads for issuance
  - Migration: 1759900500000-RenameMarketIntermediaryToRegistrant
    -- renames org type and role in organization, user, and user_role tables
    -- reassigns ACL permissions from the old role to Registrant

Removed OrganizationAdmin Role
  - OrganizationAdmin was a legacy role functionally identical to Registrant
    (assigned when an admin created an org). Merged into Registrant.
  - All users with OrganizationAdmin role reassigned to Registrant
  - ACL permissions from OrganizationAdmin (entityId=2) merged into
    Registrant (entityId=6)
  - Handled in the same migration as the rename above

Merged DeviceOwner into SiteOperator
  - DeviceOwner was a role for device owners within a SiteOperator org,
    but in practice had identical permissions and was always used alongside
    SiteOperator in access control decorators
  - All DeviceOwner users reassigned to SiteOperator
  - user_role row (id=3) renamed from DeviceOwner to SiteOperator
  - Invitation default role updated from DeviceOwner to SiteOperator
  - Migration: 1759900600000-MergeDeviceOwnerIntoSiteOperator

Removed Reviewer/SeniorReviewer from OrganizationType Enum
  - Reviewer and SeniorReviewer are roles, not organization types — they
    belong to the Admin organization. The enum values were vestigial and
    have been removed.
  - The Add User form for reviewers now uses the role dropdown directly;
    organizationType field is optional in the DTO

BUG FIXES
---------

SiteOperator Self-Registration Broken (Forbidden Resource)
  - Self-registering as a SiteOperator returned 403 "Forbidden resource"
  - Root cause: WithoutAuthGuard.resolveRegisterUser() only handled Buyer
    and Registrant org types — SiteOperator fell through to undefined,
    causing PermissionGuard to reject the request
  - Fixed by treating SiteOperator the same as Buyer in the guard (returns
    the admin user so the permission check passes)
  - Discovered via new Playwright e2e registration tests
