DREC Changelog
Report date: April 1, 2026


BUG FIXES
=========

Timestamp Format Regression
---------------------------
After upgrading TypeORM to 0.3.28, all API timestamps switched from the
standard "Z" suffix to "+00:00", breaking integrations (e.g. Powertrust
portal validation). Root causes:

  - TypeORM 0.3.28 changed internal timestamp serialization from
    .toISOString() (which outputs Z) to a Luxon-based format that
    outputs +00:00
  - Outbound Evident API calls also used Luxon's ZZ format token,
    producing +00:00 instead of Z

Fixes applied:
  - Added a global NormalizeDatesInterceptor that rewrites all +00:00
    suffixes to Z in API responses
  - Fixed the Evident issuance service to use a literal 'Z' in the
    outbound timestamp format
  - Fixed timezone.ts transformer to use .toISOString() instead of
    .format()

CORS Whitelisting
-----------------
Added stage-portal.drecs.org to the backend CORS origin allowlist after
the new staging portal URL was deployed.

Prettier CI Failures
--------------------
Fixed Prettier formatting in Postman collections and data-models.md that
were causing the "Check Docs" CI workflow to fail.

Device Registrant Display
-------------------------
The device reviews panel showed "--" for the Registrant field because the
SQL query joined user on the wrong key. Fixed by joining on
user.api_user_id = device.api_user_id (UUID) and displaying the user's
full name or email.


API CHANGES
===========

Multipart Device Registration (POST /device, PATCH /device/:id)
---------------------------------------------------------------
The POST /device endpoint now accepts multipart/form-data, allowing
document files (SF-02, SF-02C, metering evidence, single-line diagram,
project photos, screenshots, COD proof) to be uploaded alongside the
device JSON in a single request. Plain JSON is still accepted for
backward compatibility (files optional).

Certificate Log API (GET /certificate-log/issuer/certified/new/:id)
-------------------------------------------------------------------
Added a "developerId" field to each entry in perDeviceCertificateLog
responses. This contains the developer's external reference (e.g.
Powertrust Site ID) so API consumers can correlate certificates with
devices in external systems without a separate device lookup.


PREVIOUS API CHANGES (by Divine Charlotte, PRs #665, #666, #672)
================================================================

Device Registration DTO (POST /device, PATCH /device/:id)
----------------------------------------------------------
The following fields were added to the device registration and update
endpoints. These are now required for new device registrations:

  - serialNumber (required) -- unique device serial number, replaces the
    former developerExternalId as the primary device identifier. Must
    contain only letters, numbers, underscores, hyphens, or semicolons.
  - dataSource (required) -- the data source used for meter reads
    (e.g. "Engie", "BBOX", "Manual")
  - dataSourceBrand (required) -- the brand/model of the data source
    hardware
  - otherDataSource (optional) -- free-text field when dataSource is
    "Other"

The developerExternalId field is still accepted but is now optional.


NEW FEATURES
============

Solar Panel Detection via Satellite Imagery (Roboflow ML)
---------------------------------------------------------
Added an AI-powered solar panel detection feature to the device reviews
satellite map. Reviewers can click "Detect Panels" to verify that solar
installations actually exist at the claimed coordinates.

  - Uses Roboflow's zero-shot segmentation API with a "solar-panel"
    text prompt
  - Captures the visible map tiles to a canvas, crops to the center 70%,
    converts to base64 JPEG, and sends to a backend proxy endpoint
  - Draws polygon overlays on detected regions with confidence labels
  - API key is kept server-side (ROBOFLOW_WORKFLOW_URL and
    ROBOFLOW_API_KEY env vars) -- the frontend never sees it

Earlier attempts using classical computer vision (color-based and
edge/shape-based detection via OpenCV.js) produced too many false
positives on trees and failed to detect actual panels. The ML approach
works significantly better.

Satellite Map Imagery Upgrade
-----------------------------
Switched the satellite tile provider from ESRI to Google Satellite
(mt1.google.com) for higher-resolution imagery globally, especially at
high zoom levels (up to zoom 21).

Chat Message Alignment and Styling
-----------------------------------
  - Admin and Reviewer messages now consistently appear on the right side
    (own messages), regardless of the sender's email, using role-based
    alignment logic
  - Updated chat bubble colors: own messages are teal, partner messages
    are light blue

Multipart Device Registration
------------------------------
The POST /device endpoint now accepts multipart/form-data, allowing
document files (SF-02, SF-02C, metering evidence, single-line diagram,
project photos, screenshots, COD proof) to be uploaded together with the
device registration in a single request. The endpoint also still accepts
plain JSON for backward compatibility (files optional). The PATCH /device
endpoint was similarly updated to support document uploads on edit.

Document Upload on Device Edit
------------------------------
Added document upload support to the edit-device form, allowing users to
attach or replace documents after initial registration.

Client-Side OCR for Image Previews
-----------------------------------
Added Tesseract.js-based OCR to image previews in the document review
panel, allowing reviewers to extract text from uploaded device photos and
screenshots.

Reviewer Role Access
--------------------
  - Granted Reviewer and SeniorReviewer roles access to the device
    reviews UI
  - Added reviewer password-set flow via email token link
  - Added cancel button to add-user form, improved reset-password UX


INFRASTRUCTURE
==============

InfluxDB Removal
----------------
Removed all InfluxDB-related code and configuration. InfluxDB was dead
code -- meter reads are now stored directly in PostgreSQL.

  - Deleted influx-db.ts client library and influxdb.conf
  - Removed drec-influxdb service from docker-compose.yml
  - Removed @influxdata/influxdb-client dependency
  - Removed INFLUXDB_* environment variables
  - Removed InfluxDB services from CI workflow (check.yml)
  - Stubbed the migration file to a no-op (kept for migration history)
  - Removed InfluxDB references from architecture documentation

Dependabot Vulnerability Fixes
------------------------------
Resolved remaining frontend Dependabot vulnerabilities via pdfjs-dist
and picomatch upgrades, plus pnpm overrides for transitive dependencies.

Dev Environment Database Deletion
---------------------------------
The cloud-based development RDS instance (db.t3.micro) was deleted as
part of the dev environment decommission reported on March 30.
Development now runs entirely locally via Docker.

Staging Database
----------------
The staging database is a fresh clone of the production database. It is
a separate RDS instance (drec-staging.ck6auzh6fp4v.eu-west-1.rds.amazonaws.com)
and can be used safely for testing without risk to production data.
